# 00 · 从这里开始

> 文档基线：**v2.38.6**。改动功能时请一并更新本文档集。

SUB-Aggregation 是**自己部署的订阅聚合与配置生成服务**：把多个机场订阅抓下来，解析成统一节点模型，自动测活测速、按国家归属分组，最后按 mihomo / sing-box / shadowrocket / v2ray 等格式输出客户端可直接订阅的配置。

运行形态固定为**单容器 Node 进程 + 本机 SQLite 单文件**，不依赖任何第三方托管服务。

## 术语

| 术语 | 含义 |
|---|---|
| **订阅** | 一条上游订阅 URL（机场或自建），抓取后解析成节点 |
| **节点** | 一个代理服务端配置，以 `server:port:protocol` 为指纹去重 |
| **抛弃（dropped）** | 探测判定不可用或延迟超阈值，默认不进配置输出 |
| **锁定（locked）** | 用户手动标记，无视测活/延迟/禁用判定，强制进配置 |
| **策略组** | 生成配置里的 proxy-groups，客户端可见可切换 |
| **地理组** | 按节点国家归属自动生成的策略组（🇭🇰 香港、🇺🇸 美国 …） |
| **规则目录** | 从 MetaCubeX 同步的分类清单，用于按需增删分流项 |

## 三条不可动摇的约束

1. **自动生成即完整可用**：生成的配置必须自带客户端面板可见可切换的全部策略组（含国内直连、国内媒体），不允许只写 `RULE-SET,xxx,DIRECT` 让用户自己去配。
2. **分流逻辑不被性能优化波及**：提速只能动缓存、并发、时序，策略组与规则逻辑不动。
3. **只用 Docker 部署**：不再通过 Cloudflare Workers 承担任何基础能力。
