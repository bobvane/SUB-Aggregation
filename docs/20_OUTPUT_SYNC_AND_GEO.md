# 20 · 国家码检测、订阅同步与输出配置（v2.38.6）

> 本文说明：国家码两种检测操作的区别、订阅更新到输出配置的真实链路、输出配置状态字段的含义、
> 手动刷新的语义，以及 DNS / IP 缓存的策略与限制。

## 1. 国家码检测：两个不同的操作

节点页有两个入口，语义不同，**不要混用**：

| 入口 | 后端参数 | 处理范围 | 外部请求 |
|---|---|---|---|
| **补全未识别国家码**（默认） | `scope: 'unlocated'` | 只处理当前**没有有效国家码缓存**的服务器 | 只为这些服务器解析域名 + 查询归属地 |
| **全量重检**（需二次确认） | `scope: 'all'` | 全部服务器 | 仍**优先命中缓存**（域名 6 小时 / 归属地 30 天），只有未命中的部分才外发请求 |

要点：

1. **"补全"在全部已识别时什么都不做**：不会发起任何外部查询，界面明确显示
   「全部服务器已有有效国家码，本次无需检测，没有发起外部查询」。
2. **"全量重检"不等于"所有 IP 都重新查一遍"**：缓存仍在有效期内就复用；真正外发多少请求，
   结果窗口的「外部请求（真实计数）」会如实列出。
3. 两个操作都**不会**重新拉取订阅、不会重新测速。

### 统计口径（不可相加）

| 字段 | 口径 | 含义 |
|---|---|---|
| `serverTotal` | 服务器级 | 参与检测的服务器数（按 `server` 地址去重，不是节点数） |
| `targets` | 服务器级 | 本次真正要检测的服务器数 |
| `unlocatedBefore` / `unlocatedAfter` | 服务器级 | 检测前 / 后仍无有效国家码的服务器数 |
| `resolved` / `failed` / `unresolved` | 服务器级 | 识别成功 / 已查询但无国家 / 解析不出 IP 未查询 |
| `cached` / `queried` | **IP 级** | 命中归属地缓存的 IP 数 / 实际查询的 IP 数 |
| `requests.dnsCached` / `dnsQueried` / `dohFallback` | 请求级 | 命中 DNS 缓存数 / 发出的 DoH 请求数 / 其中回退 Cloudflare 次数 |
| `requests.ipApiRequests` | 请求级 | 实际发出的 ip-api 批量请求数 |
| `requests.rateLimited` | 请求级 | 因 15 次/分钟限流本次未查询的 IP 数（留待下次重试） |

**服务器级与 IP 级不能相加**：多个服务器可能解析到同一个 IP，IP 查询会去重。

## 2. 订阅更新 → 输出配置的真实链路

```text
[手动] 更新订阅按钮
[自动] 每小时 tick + sub_update_interval 到点
        │
        ▼
subscription.service.update()
  fetch → parse → applyRules → diff → merge(tombstone) → 写 KV nodes:{subId}
        │
        ├─ 成功落库后：config_version + 1（配置快照失效）★ v2.38.6 新增
        │
        ├─ 后台：probeAllNodes（测速，fire-and-forget）
        └─ 后台：prewarmIpGeo（国家码预填充）

输出配置请求（预览 / 下载 / /sub/...）
  mihomo  → 命中当前版本快照则直接返回；版本不符则重新生成并写回
  其他格式 → 每次实时生成
```

### 快照失效触发点（全部真实存在）

- **订阅更新成功落库**（手动与自动共用 `subscription.service.update`）
- 订阅启用 / 停用
- 禁用节点 / 锁定节点
- 规则选择、整组开关、自定义规则增删改
- 手动「刷新输出配置」

失败语义：订阅拉取/解析/落库失败时**不会**失效缓存，也不会把订阅标记为已更新。

### 并发生成保护

`config.generate()` 在**开始生成前**捕获 `config_version`，写回快照时沿用该版本。
若生成期间有更新把版本推进，这份内容只会写到旧版本键（无人读取），
下一次请求必然重新生成 —— 不会出现"旧内容盖上新版本"。

## 3. 输出配置状态（`GET /api/output/status`）

| 字段 | 含义 |
|---|---|
| `nodes.ingested` | 去重后的全部节点数（含停用订阅） |
| `nodes.inOutput` | **真正进入输出配置**的节点数（与 `getNodes()` 完全同口径） |
| `nodes.excluded.subscriptionDisabled` | 因订阅停用而排除 |
| `nodes.excluded.disabled` | 因手动禁用而排除 |
| `nodes.excluded.dropped` | 因抛弃（健康状态机 / 慢节点阈值）而排除 |
| `nodes.excluded.removed` | 因删除（tombstone）而排除 |
| `dataVersion` | 当前 `config_version`（数据版本） |
| `snapshot` / `stale` | 当前版本是否已有 mihomo 快照 / 是否落后 |
| `lastGeneratedAt` | 最近一次成功生成 mihomo 的时间 |
| `formats.mihomo` / `formats.others` | mihomo 走快照；其他格式实时生成 |
| `background.geoRetryActive` | 国家码补全是否仍在后台重试（唯一被持久化记录的任务状态） |

排除原因**互斥**（同一节点只计一次），顺序：停用订阅 → 锁定豁免 → removed → 禁用 → 抛弃。

页面明确区分"尚未生成"和"失败"：没有快照时显示「待重新生成」，不当作错误。
后台任务状态若没有记录，显示「未记录」，不虚构进度。

## 4. 手动刷新输出配置（`POST /api/output/refresh`）

**只做三件事**：让快照失效 → 立即生成 mihomo → 返回真实结果（节点数 / 耗时 / 字节数）。

**不做**：重新拉取订阅、重新测速、强制国家码全量检测。

并发保护：同一进程内重复点击返回 `409 REFRESH_IN_PROGRESS`，避免并发写入与无意义的版本递增。

## 5. DNS 与归属地缓存

| 缓存 | 键 | TTL | 说明 |
|---|---|---|---|
| 域名 → IP | `dns_ip:{server}` | **6 小时** | v2.38.6 新增；避免每次预填充都重新 DoH |
| IP → 国家 | `ip_geo:{ip}` | 30 天 | 失败不写缓存（允许重试） |
| server → 国家 | `ip_geo:{server}` | 30 天 | 统计与命名的口径来源 |

外部请求链路：

1. **域名解析**：先查 `dns_ip`；未命中 → Google DoH（`dns.google`）；失败才回退 **Cloudflare DoH**（`cloudflare-dns.com`）。
   纯 IP 服务器直接短路，不发 DoH。
2. **归属地查询**：命中 `ip_geo:{ip}` 则跳过；未命中 → ip-api 批量接口，
   **每批 ≤100 IP、15 次/分钟、单次调用最多 5 批**；超限的 IP 计入 `rateLimited`，
   保持"未识别"并在下次补全或每分钟重试（最多 10 轮）时继续处理，**不会静默丢失**。

限制说明：系统**没有**全局每日配额计数器，因此无法断言"每天一定不超过某个额度"；
上面的计数只反映单次操作的真实请求量。需要评估额度时，请以这些计数 + 实际触发频率为准。

## 6. 自动更新间隔的真实语义

`sub_update_interval`（0–24 小时，0 = 关闭，默认 24）**只控制订阅拉取频率**。
拉取成功后才串接测速与国家码预填充；它**不**控制配置生成，也不代表"下游已处理完"。

- 调度：每分钟 tick 检查、整点执行，到点判定留 1 分钟余量避免漂移；
- 多订阅：串行逐个更新；
- 下游失败不影响本次订阅更新结果（只记录日志）；
- 想让输出配置立刻反映最新节点：**合并后自动失效**（v2.38.6 起），无需手动操作。
